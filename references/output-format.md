# 输出格式与完整示例

## 默认简评

先给一句结论：**约 X/10，程度。** 同时交代主要任务是用户给定还是本次假设，以及只评当前截图的范围。

随后给最有影响的具体问题。每条用自然语言包含：

> **位置或原文｜主维度｜已见证据 → 影响或推测 → 修改方向**

选几条足以解释分数的问题，不为凑数量找错。再说明值得保留的关系及重要待判项。用户只问分数时可以压缩，仍要有证据；不要默认重述整份标准。

## 完整评审的必要字段

| 字段 | 内容 |
|---|---|
| 评分与范围 | 约 X/10、粗档位、页面/状态/显示范围、是否仅视觉暂评 |
| 任务依据 | 用户明确提供的内容；本次假设单独标明 |
| 主要问题 | 问题 ID、位置/原文、主维度、已见证据、影响（注明推测）、修改方向 |
| 成立之处 | 本次确实检查过、应继续保留的内容或关系 |
| 待判项 | 缺什么材料、它将影响哪个结论；不要只写“需要更多背景” |
| 复查 | 修改后检查什么；不声称已做未执行的测试 |

A/B/C 用于归属，可按需要写“未见明确、局部、明显、待判”；不生成维度加权总分。无需增加生成概率、置信度百分比或小数分。

## 双图比较

两页各自标注任务/假设、范围、分数；逐一比较同类角色的表达、注意力与构成。接着指出真正拉开差距的独立证据，以及哪些只是任务或状态差异。不能把一页的居中当问题，却忽略另一页同角色也居中。

只支持局部比较时，不强排整体高低。可把主观直觉单列，但不伪装成由框架证实的结论。

## 调分

写明旧分、新分和新证据/规则改变了哪个判断。按整体影响重新定档，保留仍成立的关系；不要把用户不断补充问题变成自动涨分机制。

## 完整示例：计划支出周历页

对应 [校准案例中的 C03 原图及背景](calibration-cases.md)。以下是一个可直接交给用户的评审，不是要求所有输出逐字复现的模板。任务背景和问题粒度改变时，可以有不同的记录顺序与粗分，不必补找同样数量的问题。

---

**暂评约 4/10，AI 味中等。** 任务未明确提供，先按“查看本月计划支出及待出账项目”评当前首屏；列表下方没有完整展示。

目前影响较大的问题集中在 C「构成关系与视觉平衡」。

**C-01，账单卡片内部的留白。** 左侧图标与卡片边缘、右侧金额及状态与边缘的可见空隙不协调。先检查图标占位框，再按整组视觉外缘调整，避免只让坐标相等却看起来仍不均。时间线是卡外关系，不能解释这一卡内问题。

**C-02，明细区域的缩进与重心。** 时间线之后卡片继续右缩，右侧接近页面边缘；连续底板形成偏右重量，右下深色按钮进一步加重同侧。可先调整时间线与卡片的缩进，再放回整页检查。缩进、外部留白和偏右属于这条问题链，合并记录，不重复累计。

**C-03，悬浮按钮遮挡记录。** 当前截图中部分记录信息被按钮压住。调整列表位置后仍可能存在遮挡，需要独立的按钮避让空间。这条只记录信息被遮住的影响，按钮对同侧重量的影响沿用 C-02，不另计一次。

值得保留：金额重点明确，“7笔周期计划”提供数量，“待出账”提供状态；重复账单结构基本稳定。当前没有看到明显的套话扩写或所有模块同级争抢。

待判有两处。月份行与箭头已有导航线索，需要确认是独立导航还是内容标题；前者居中可以成立，后者可按本页靠左标题规则讨论调整。选中18日却展示31日的明细，是否冲突取决于列表是否按选中日期筛选，需要一次切换日期的状态对照。当前都不作为已确认缺陷计入，也不把未知算作零问题。

修改后复查：在相同显示范围内检查卡内两侧留白、明细区域重量及按钮遮挡；明确月份行职责后检查其基准，如果能操作，再检查日历与列表的关系。

---

示例没有声称做过用户测试、测得原稿像素或知道制作过程。0–10 仍为粗档判断，不是以上三条各值若干分的相加。
